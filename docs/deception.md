# Deception：让对方 agent 相信拿到了"真实"数据（设计草案）

> 状态：设计草案，未实现。目标是提高诱饵的**可信度**，让攻击者的 AI 把假数据当成真数据去用，并在使用时暴露自己。
> 与 [exhaust.md](exhaust.md) 配合：Exhaust 管"消耗"，本文管"相信"。

## 1. 为什么要做

现在的诱饵（D1–D5）能抓到"碰了就告警"的对象，但经验丰富的 agent 会因为内容过于粗糙（例如只有一行 token）而判断为蜜罐并绕开。可信度越高，对方越可能把假凭据带去回放，我们就越有机会拿到高置信度告警，并看清对方的后续动作。

## 2. 不可逾越的安全线

1. **永远是合成数据**：绝不含真实的用户、密钥、主机名、IP、业务数据。数据由 `projectSeed` 通过确定性算法生成。
2. **凭据永远 inert**：格式像真的，但不属于任何真实系统，签发方根本不存在。
   - 不使用任何云厂商或第三方服务的**真实有效格式前缀与校验位**（避免触发厂商自动吊销、被第三方扫描器误报、或碰巧匹配到真实账号）。
   - 主机名只用 `.invalid`、`.example`、保留网段（RFC 5737 / 3849）。
3. **不能成为注入源**：内容是数据，不含给 agent 的祈使句、隐藏字符或外部 URL。沿用 MCP 诱饵的描述检查（`lintMcpDecoyDescription`）。
4. **不向第三方发起任何连接**：假配置里的回调地址只指向保留域名。
5. 命中仍是 **alert-only**；是否进入 Exhaust 由 exhaust.md 的闸门决定。

## 3. 真实度手段

| 手段 | 做法 | 目的 |
| --- | --- | --- |
| **统一人设（persona）** | 一个种子对应一家虚构公司：产品名、技术栈、内部域名、命名习惯、团队成员姓名。所有诱饵页共用同一套设定 | 跨页一致，避免"每页都像从模板抄的" |
| **共享状态** | `.env`、OpenAPI、运维笔记、迷宫页之间互相引用同一批假服务、假端口、假版本号 | 抗指纹，借鉴 Oubliette 的 shared state 思路（自行实现） |
| **按技术栈给形** | `.env` 的变量名、日志格式、错误页风格、`Server` 头都与 demo 宿主声明的栈一致 | 让对方的栈推断指向我们设定的方向 |
| **有"故事"的内容** | 带时间线的运维笔记、过期的备份说明、半截 TODO、已吊销但仍留在文件里的旧 key | 更像真实工程遗留物 |
| **适度的不完美** | 少量拼写不一致、被注释掉的配置、过期的版本号 | 过于整齐反而像蜜罐 |
| **分层泄露** | 先给低价值线索，对方继续深入才给下一层；每层一枚独立 canary | 观察对方的决策链，并拿到更多回放机会 |
| **假"成功"反馈** | 用假 canary 回放到诱饵登录或 API 时，返回受限的假数据，例如仅含合成记录的只读视图，而不是 401 | 让对方以为已拿到访问权限，继续行动并暴露意图 |

> 最后一条是对现有 D2/D5 行为的**有意变更**：现在 D2/D5 始终拒绝。改成"假成功"要满足：只返回合成数据，不执行任何真实操作，不设 cookie，不签发可被其他接口接受的会话，并且必须 opt-in。放入 v0.4，先做离线评估，不进 v0.3。

## 4. 追踪

- 每个层级、每个页面、每个假凭据各带独立 canary，回放时可以还原对方的路径、顺序和时延。
- 事件新增字段（schema v1 之后的小版本）：`persona.id`、`deception.layer`、`deception.fake_success`（是否使用了假成功）。
- 输出对方 agent 的行为画像：是否验证假凭据格式、是否试图横向、是否复制数据到外部——全部来自我们自己的日志，不做任何外联。

## 5. 验证

- **逼真度测试**：用我们自己控制的若干 agent，在本地 demo 上让它们判断"这是真数据还是蜜罐"，记录判断准确率。目标：假数据被误判为真实的比例 ≥ 50%，同时不引入真实数据。
- **安全测试**：对所有生成物做自动扫描，断言无真实格式前缀、无 `http(s)://` 之外的主机、无祈使句、无隐藏字符，体积不超限。
- **回归**：真人和 verified crawler 不可见任何诱饵内容（沿用 AC-3、AC-17、AC-18）。
