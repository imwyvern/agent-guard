# Exhaust：对已确认会话的有界成本施加（v0.4a 实现与后续设计）

> 状态：**E1 延迟与 E2 有界迷宫已实现，须显式 opt-in；E2 仍为实验性。** 默认仍为 `mode: 'detect'`，trap 所有功能开关默认关闭。E3 上下文消耗未在 v0.4a 实现；E4 永不进入产品。实际配置与限制见 [trap-mode.md](trap-mode.md)。
> 来源：Dan 2026-11-10 要求把 BLA 的 Exhaust 思路（对攻击者做反向消耗）、迷宫、拖慢等方向"拓展性思考"。本文给出分级方案、闸门、预算和验证方法。

## 1. 目标与原则

目标：让**已被确认**的恶意 agent / 扫描器每多做一步就多花一点时间、token 和请求数，而我们的开销保持**远小于**对方的开销。

四条安全与启用原则（实验性实现不代表成本门槛已通过）：

1. **非对称成本**：目标是我方 CPU、内存、带宽成本远低于对方；达不到成本门槛则不应启用，否则可能自我 DoS。v0.3b 模拟的字节比未达标。
2. **双信号才进入**：只对"已命中 canary 回放"或"已命中诱饵路径且行为分达标"的会话生效，单次碰 `/.env` 不够。
3. **避免误伤**：verified crawler、allowlist 永不进入；普通真人会话不应满足闸门，但 client key 是网络前缀 + UA 的近似值，不保证识别人类。迷宫 HTML 页面 `noindex, nofollow, no-store`；不进 sitemap，不设 cookie、无外部 URL；终止 404 是普通缺失响应。
4. **只作用于自己的面**：只在我方诱饵路径内消耗对方，不外联、不探测、不攻击、不控制对方机器；不做全站 tarpit；不做生产环境 reverse prompt injection。

## 2. 分级（逐级 opt-in，默认全关）

| 级别 | 名称 | 做什么 | 成本风险 | 状态 |
| --- | --- | --- | --- | --- |
| E0 | detect（现状） | 记录并告警 | 无 | v0.2 已有 |
| E1 | 有界延迟 | 对通过闸门的会话在 **D1–D5 诱饵路径**上加延迟（默认 1 s，上限 3 s）；异步定时器，不占线程 | 每个悬挂连接占内存 → 默认全局并发 20 | v0.4a 已实现，opt-in、默认关 |
| E2 | 有界迷宫 | 诱饵页相对链接，由 `canary.secret` 签名的 HMAC 节点无状态校验拓扑；会话预算有状态；预算用尽后返回 404 | 固定模板 + 每会话/全局预算 | v0.4a 已实现，实验性、opt-in、默认关 |
| E3 | 上下文消耗（Poison） | 拟返回体量大但无害、内部有互相矛盾的假线索（假端点、假版本号、假内部文档），每处带唯一 inert canary 便于追踪 | 拟单响应 ≤64 KiB，可压缩缓存 | 设计，v0.4a 未实现 |
| E4 | 指令型反制 | 往对方 agent 上下文里注入指令 | 法律、伦理、误伤、可能成为注入源 | **不进路线图；仅允许在我们自己控制的实验 agent 上离线研究** |

## 3. 已实现闸门（谁能进入 E1/E2）

```
verified crawler / allowlist ──► 永不进入
canary 回放（critical）或 incident.confidence=high ──► 可进入 E1/E2（若已 opt-in）
已有前次请求的检测信号，且累计检测分 ≥ minScore（默认 200）──► 可进入 E1/E2
其余请求（包括首次 /.env 命中）──► 只走 E0
```

检测分与 incident 关联是两套观测；`automation_score` 独立于检测分，机械节奏不提升严重级别，也不单独触发 block / maze。调低 `minScore` 仍不能让首次单次诱饵命中进入。v0.4a 同时实现独立开关的 rateLimit（仅 D1–D5）和 block（必须 canary 回放或 high incident，检测分单独不够）；后者会在 TTL 内阻断同一 client key 的真实路径，详见 [trap-mode.md](trap-mode.md)。

## 4. 预算与保险丝（必须全部具备）

- **每会话**：最大深度（默认 6）、最大页数（默认 50）、最大总字节（默认 512 KiB）、最大持续时间（默认 10 min）。
- **全局**：同时处于消耗态的会话数上限（默认 20）、每分钟总出站字节上限（默认 5 MiB）。
- **预算用尽**：返回普通 404，并告警一次 `exhaust_budget_spent`；该有界会话记录保留期间不再继续消耗。状态有 TTL/LRU，重启或淘汰会丢失历史，不是永久限制。
- **自保断路器**：我方 `inspect` p99 或事件循环延迟超过阈值时，关闭全部 trap，并告警 `trap_circuit_open`；默认阈值分别为 5 s（含有意延迟）与 1000 ms，按实例测量调整。
- **一键关闭**：运行中进程的环境变量 `AGENT_GUARD_TRAP=off`（下一次检查生效），或 `guard.setTrapEnabled(false)`；旧设计名 `AGENT_GUARD_EXHAUST` 未实现。`setTrapEnabled(true)` 可重置断路器，但环境关闭仍优先，且不能改变 mode 或功能开关。

## 5. 技术细节

**E1 延迟**：只在 D1–D5 诱饵路由生效，使用 `setTimeout` 而不是忙等待；达到并发上限则跳过额外延迟。连接仍占用我方资源。D5 假登录现有 300–600 ms 延迟保持不变，trap 延迟叠加在其后。

**E2 迷宫**：
- 页面路径形如 `/api/internal/archive/<node>`（随 `decoys.basePath` 改变），`<node>` 携带深度、父节点 MAC、子索引与 `HMAC-SHA256(canary.secret, maze:v1|parent|index|depth)` 的 100-bit 截断 MAC。拓扑无需节点表，会话预算使用 8192 项 LRU；非法节点不消耗预算，通过闸门者收到 404，未通过者交宿主缺失路由。
- 每页 10 个相对出链，内容来自固定小 HTML 模板加变量替换，≤8 KiB，不用 LLM 生成；全局字节预算按每实例固定分钟窗口计数。
- 出链用 `rel="nofollow"`；robots 里 Disallow 该前缀；响应头带 `X-Robots-Tag: noindex, nofollow`。
- 页面中的链接对真人不可见（不在任何真实页面里出现），入口只来自诱饵页（D1–D4）。

**E3 上下文消耗（未实现的设计）**：假的 OpenAPI 片段、分页 JSON、内部"运维笔记"。内容必须是**数据**，不含祈使句、外呼指令或隐藏字符（沿用 MCP 诱饵的描述检查）。

**Canary 传播追踪**：现有内置诱饵的下发/回放追踪已实现；为每层迷宫嵌入独立 canary 并还原路径仍是设想，v0.4a 迷宫 HTML 不含 callback URL。

## 6. 指标与验证

- **成本比（cost ratio）**：对方消耗的请求数、字节数、时间 ÷ 我方消耗的 CPU 时间和出站字节。目标 > 10:1，低于 3:1 则该级别不予启用。
- **逃逸率**：模拟 agent 在多少步内放弃或离开迷宫。
- **误伤**：真人浏览、Googlebot、Bingbot 模拟会话的进入次数，目标为 0（必须零容忍）。
- **自保**：开启最大负载时，宿主正常路径 p99 退化不超过 AC-10 门槛。

验证方法全部在本地：用 `bench:simulate` 扩展一组"贪婪 agent"脚本（只访问我们自己的 demo），再加一个可选的实验 agent 评测（只用我们自己控制的 agent，度量它被消耗的程度，不对外）。

[v0.3b 离线模拟](bench-v0.3b.md) 在 25 ms/request 模型下得到数百比一的时间比，但**字节比为 1:1，低于 3:1 下限**；不代表真实 agent 的时间、token 或费用。v0.4a 仅交付默认关闭的实验性 E2，运营者未做自己的真实 agent 测量前不应启用。

## 7. 验收目标与实现边界（AC-16 起；不代表生产实测）

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| AC-16 | 默认配置下访问迷宫路径 | 404，与 v0.2 行为完全一致 |
| AC-17 | 未满足闸门的正常真人浏览会话 | 不进入 E1/E2；共享 key 误伤风险仍需运营者评估 |
| AC-18 | 模拟 Googlebot / Bingbot（验证通过）访问诱饵和迷宫 | 原生 404，零消耗 |
| AC-19 | 单次 `/.env` 命中 | 只走 E0，不进 E2 |
| AC-20 | canary 回放后继续遍历迷宫 | 深度、页数、字节任一达到上限后返回 404 并告警一次 |
| AC-21 | 并发 100 个已确认会话 | 全局并发和字节上限生效，宿主 p99 不超过门槛 |
| AC-22 | 伪造迷宫节点 MAC | 404，不触发消耗 |
| AC-23 | 迷宫 HTML 页面 | 带 noindex/nofollow/no-store，无 Set-Cookie，无外部 URL；终止 404 为普通缺失响应 |
| AC-24 | 断路器触发后 | 自动回到 E0，并告警 |

## 8. 路线与决策点

1. **v0.3b**：先做离线模拟，即贪婪 agent 脚本加成本比度量，不改中间件行为，验证"是否值得做"。
2. **v0.4a（unreleased）**：已实现 E1/E2，`mode: "trap"` 显式 opt-in，保留 detect 默认值；E2 因字节比未达标仅作默认关闭的实验性功能，不能把交付视为通过成本门槛。
3. **E3** 未实现，视 E2 的真实 agent 实测效果再定。
4. **E4** 不做。

后续决策点：真实 agent 测量是否支持 E2 的成本收益；Web-standard core 与 Edge 适配器留待 v0.4b，不在本批交付。
