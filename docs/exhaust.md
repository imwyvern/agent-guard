# Exhaust：对已确认恶意 agent 的有界成本施加（设计草案）

> 状态：**设计草案，未实现。** 默认配置下完全不生效；`mode` 目前仍只接受 `"detect"`。
> 来源：Dan 2026-11-10 要求把 BLA 的 Exhaust 思路（对攻击者做反向消耗）、迷宫、拖慢等方向"拓展性思考"。本文给出分级方案、闸门、预算和验证方法。

## 1. 目标与原则

目标：让**已被确认**的恶意 agent / 扫描器每多做一步就多花一点时间、token 和请求数，而我们的开销保持**远小于**对方的开销。

四条硬原则（违反任何一条即不得实现）：

1. **非对称成本**：我们每个响应的 CPU、内存、带宽必须比对方处理它的成本低一个数量级以上；否则就是自我 DoS。
2. **双信号才进入**：只对"已命中 canary 回放"或"已命中诱饵路径且行为分达标"的会话生效，单次碰 `/.env` 不够。
3. **永不伤及无辜**：verified crawler、allowlist、带人类特征的会话永不进入；所有页面 `noindex, nofollow, no-store`；不进 sitemap，不设 cookie。
4. **只作用于自己的面**：只在我方诱饵路径内消耗对方，不外联、不探测、不攻击、不控制对方机器；不做全站 tarpit；不做生产环境 reverse prompt injection。

## 2. 分级（逐级 opt-in，默认全关）

| 级别 | 名称 | 做什么 | 成本风险 | 状态 |
| --- | --- | --- | --- | --- |
| E0 | detect（现状） | 记录并告警 | 无 | v0.2 已有 |
| E1 | 有界延迟 | 对已确认会话在**诱饵路径**上加固定上限延迟（例如 1–3 s）；异步定时器，不占线程 | 每个悬挂连接占一点内存 → 并发上限 | 设计 |
| E2 | 有界迷宫 | 诱饵页互相链接，由 HMAC(seed, path) 无状态生成；深度、每会话字节、全局速率都有上限；预算用尽后返回 404 | 生成成本 → 预渲染模板 + 全局字节预算 | 设计 |
| E3 | 上下文消耗（Poison） | 返回体量大但无害、内部有互相矛盾的假线索（假端点、假版本号、假内部文档），每处带唯一 inert canary 便于追踪 | 响应体大 → 单响应 ≤64 KiB，可压缩缓存 | 设计 |
| E4 | 指令型反制 | 往对方 agent 上下文里注入指令 | 法律、伦理、误伤、可能成为注入源 | **不进路线图；仅允许在我们自己控制的实验 agent 上离线研究** |

## 3. 闸门（谁能进入 E1–E3）

```
verified crawler / allowlist ──► 永不进入
没有 canary 回放且行为分 < 阈值 ──► 只走 E0
canary 回放（critical）──► 可进入 E1–E3（若已 opt-in）
诱饵命中 + 行为分 ≥ 阈值（路径枚举、无 Referer、请求节奏机械、UA 声明为 AI 但不通过验证）──► 可进入 E1–E2
```

行为分沿用 roadmap v0.3 的会话关联：对每个客户端 key 做有界计数（诱饵命中数、枚举路径数、请求间隔方差）。分数只用于闸门，不用于封禁。

## 4. 预算与保险丝（必须全部具备）

- **每会话**：最大深度（默认 6）、最大页数（默认 50）、最大总字节（默认 512 KiB）、最大持续时间（默认 10 min）。
- **全局**：同时处于消耗态的会话数上限（默认 20）、每分钟总出站字节上限（默认 5 MiB）。
- **预算用尽**：回到原生 404，并告警一次 `exhaust_budget_spent`；不再继续消耗。
- **自保断路器**：我方 `inspect` p99 或事件循环延迟超过阈值时，自动关闭 E1–E3，并告警 `exhaust_circuit_open`。
- **一键关闭**：`mode` 回到 `"detect"` 或环境变量 `AGENT_GUARD_EXHAUST=off` 立即生效，无需重启。

## 5. 技术细节

**E1 延迟**：只在诱饵路由生效，使用 `setTimeout` 而不是忙等待；每个连接的内存占用远小于对方保持连接的成本。D5 假登录现有 300–600 ms 延迟保持不变。

**E2 迷宫**：
- 页面路径形如 `/api/internal/archive/<node>`，`<node>` 是 base32 编码的 `HMAC(seed, parent|index|depth)` 截断值；服务端无需存状态，校验 MAC 即可确认节点是否合法，非法节点直接 404。
- 每页 8–12 个出链，内容来自固定的几个预渲染模板加变量替换，不用 LLM 生成。
- 出链用 `rel="nofollow"`；robots 里 Disallow 该前缀；响应头带 `X-Robots-Tag: noindex, nofollow`。
- 页面中的链接对真人不可见（不在任何真实页面里出现），入口只来自诱饵页（D1–D4）。

**E3 上下文消耗**：假的 OpenAPI 片段、分页 JSON、内部"运维笔记"。写法要点：内容是**数据**，不含祈使句、URL 之外的指令或隐藏字符（沿用 MCP 诱饵的描述检查）。每处嵌入的 canary 都是 inert，可以在日志里看出对方走到了哪一层、把哪些假线索带去了别处。

**Canary 传播追踪**：迷宫节点内的每个 canary 带上层级和路径指纹，对方若把其中一个拿去回放，就能还原它走了哪条路径。

## 6. 指标与验证

- **成本比（cost ratio）**：对方消耗的请求数、字节数、时间 ÷ 我方消耗的 CPU 时间和出站字节。目标 > 10:1，低于 3:1 则该级别不予启用。
- **逃逸率**：模拟 agent 在多少步内放弃或离开迷宫。
- **误伤**：真人浏览、Googlebot、Bingbot 模拟会话的进入次数，目标为 0（必须零容忍）。
- **自保**：开启最大负载时，宿主正常路径 p99 退化不超过 AC-10 门槛。

验证方法全部在本地：用 `bench:simulate` 扩展一组"贪婪 agent"脚本（只访问我们自己的 demo），再加一个可选的实验 agent 评测（只用我们自己控制的 agent，度量它被消耗的程度，不对外）。

## 7. 验收用例（草案，AC-16 起）

| 编号 | 用例 | 期望 |
| --- | --- | --- |
| AC-16 | 默认配置下访问迷宫路径 | 404，与 v0.2 行为完全一致 |
| AC-17 | 真人浏览会话（带 Referer、人类节奏） | 从不进入 E1–E3 |
| AC-18 | 模拟 Googlebot / Bingbot（验证通过）访问诱饵和迷宫 | 原生 404，零消耗 |
| AC-19 | 单次 `/.env` 命中 | 只走 E0，不进 E2 |
| AC-20 | canary 回放后继续遍历迷宫 | 深度、页数、字节任一达到上限后返回 404 并告警一次 |
| AC-21 | 并发 100 个已确认会话 | 全局并发和字节上限生效，宿主 p99 不超过门槛 |
| AC-22 | 伪造迷宫节点 MAC | 404，不触发消耗 |
| AC-23 | 所有迷宫响应 | 带 noindex/nofollow/no-store，无 Set-Cookie，无外部 URL |
| AC-24 | 断路器触发后 | 自动回到 E0，并告警 |

## 8. 路线与决策点

1. **v0.3b**：先做离线模拟，即贪婪 agent 脚本加成本比度量，不改中间件行为，验证"是否值得做"。
2. **v0.4**：若成本比达标，再实现 E1/E2，`mode: "trap"` 作为显式 opt-in，并保留 detect 作为默认值。
3. **E3** 视 E2 的实测效果再定。
4. **E4** 不做。
